AGENT ARCHITECTURE
Agent 体系设计逻辑

      
01 · 总体编排
全局 Harness 管阶段，专用 Agent 管任务
原始事件日志先进入 Session Blackboard。阶段路由 Agent 只负责校验状态切换；讨论促进与方案综合并行；破冰和投票是受路由调用、可审计的 Workflow。

      
02 · 路由与切换
事件触发 + 防抖 + 守卫条件
  • 开场静默达到阈值 → 破冰 Workflow
  • 连续两次收敛建议 → 发散切换到收敛
  • MooTu/Core 明确提示用 Pod 投票 → 投票 Workflow
  • 候选快照未形成时禁止正式收票；投票完成后进入结果确认

      
03 · 分工
讨论判断与方案整理分离
  • 讨论促进 Agent：参与、发散、流动、邀请和阶段提示
  • 方案综合 Agent：持续归类关键词，冻结可投票候选
  • 破冰 Workflow：灯光接力与首次发言邀请
  • 投票 Workflow：候选展示、Pod 收票、计数与结果确认

      
04 · 输入与输出
只读可观察证据，输出结构化动作
输入包括逐字稿、说话人、时间、现场/设备事件、参与与流动指标。输出包括阶段、策略、目标成员、Core 移动/朝向/姿态/语音/屏幕，以及 Pod 灯光、温度、振动与呼吸反馈。

      
05 · 记忆
事件日志、共享黑板与局部工作记忆
  • Event Log：不可变的事实来源
  • Blackboard：当前阶段、参与者、候选快照和票仓
  • Agent 工作记忆：最近 8 个观察、上一动作、预期效果和缺失证据
  • 候选方案进入投票后冻结，避免继续漂移

      
06 · Tools 与 Skills
按阶段发现 Skill，按顺序调用 Tool
Skill Registry 根据当前 phase 暴露 phase-routing、icebreaker-protocol、discussion-facilitation、candidate-synthesis 或 voting-protocol。讨论 Agent 的 Tool 链依次读取窗口、参与度、流动性、发散度、记忆与冷却，再评估候选、生成动作、分发 Core/Pod 指令并记录预期效果。

      
07 · 决策边界
DeepSeek 提案，确定性 Harness 最终批准
模型负责理解具体语义、总结方案和生成自然语言；Harness 负责策略白名单、证据完整性、收益与打断成本、置信度、冷却时间、阶段防抖和次数上限。模型不能绕过这些守卫直接控制硬件。
